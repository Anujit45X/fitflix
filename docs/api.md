# API conventions
All new clients use /api/v1. Recovered /api endpoints remain aliases.
JSON request/response bodies; dates are YYYY-MM-DD interpreted in the profile timezone; timestamps are UTC. Authenticated calls use Authorization: Bearer <in-memory access token>. Browser refresh/logout require the exact configured Origin and the HttpOnly SameSite=Strict cookie. Credentials are never URL parameters.

| Area | Endpoints |
| --- | --- |
| Auth | POST /auth/register, /auth/login, /auth/refresh, /auth/logout, /auth/forgot-password, /auth/reset-password |
| Profile | GET /me, GET/PUT /profile, PUT /goals |
| Foods | GET /foods?search=&category=&sort=name&page=0 (30 per page), /foods/categories, /foods/{id}/servings; POST /foods; GET/POST /favorites |
| Diary | GET /meals?date=; POST /meals; PUT/DELETE /meals/{id}; POST /meals/copy |
| Thali | GET /recipes (ingredient estimates); POST /meals or /saved-meals using selected foodId/grams |
| Saved | GET/POST /saved-meals; POST /saved-meals/{id}/log; DELETE /saved-meals/{id} |
| Water/weight | POST /water; DELETE /water/{id}; POST /weight; POST /activity |
| Summary | GET /dashboard?date=; GET /analytics/summary?from=&to= (maximum 90 days) |
| Workouts | GET /workouts/templates; GET /workouts?from=&to=; POST /workouts; PUT/DELETE /workouts/{id} |
| Privacy | POST /account/export and DELETE /account (current password body required) |

Meal body: {"date":"2026-10-07","mealType":"LUNCH","items":[{"foodId":168878,"grams":150}]}. Server reads source nutrients and stores a snapshot; the client cannot submit authoritative calories. Saved meals add name and optional plannedDate. Workout schedule: {"templateId":"home-beginner","date":"2026-10-07"}; completion: {"completed":true}. Repeating a workout schedule for the same user/template/day is idempotent. Repeating a food or water log intentionally creates another entry; buttons disable while pending. Network-uncertain POST retries are not automatic.

Validation errors: HTTP 400 with message and optional fields. 401 expired/missing authentication; 403 denied permission; 404 missing/not-owned private record; 409 conflicting invariant; 429 auth rate limit with Retry-After; 503 unavailable email integration. Generic 500 responses do not expose request values. Food lists paginate; date-bounded diary/workout summaries are range-limited rather than paginated.

OpenAPI JSON is generated by the running backend at /v3/api-docs and protected by role. Account exports exclude hashes and session credentials. Deletion cascades through owned records, removes private food references first and deletes linked visitor records. Shared source foods remain.
