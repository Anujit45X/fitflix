# Analytics contract
Personal date range is inclusive, 1–90 days, bounded by the user's local today. Days without logs are included in consistency and daily averages. Calorie/protein adherence denominators use meal-tracked days. Missing daily weights stay null; latest known weight can carry forward for goal progress only. Seven-day rolling weight average uses recorded values in that trailing calendar window. Targets use DailyTarget snapshots; dates with no snapshot use current estimates and are explicitly labeled untracked.
Fitplix Score = 25×calorie adherence + 20×protein fulfillment + 15×water fulfillment + 15×activity fulfillment + 15×logging + 10×weight progress. Fractions are clamped 0–1, daily calorie adherence is binary ±10%; activity=max(steps/8000,minutes/30); score is 0 for wholly untracked days. Period scores are arithmetic means including untracked days. Maintenance goal progress uses tolerance ±2% from starting weight. Insufficient history yields no trend claim.
Product reporting uses UTC calendar days and explicit demo/real datasets. Active = authenticated intentional login, nutrition, weight, activity, goal, plan, analytics or food-search event; registration and onboarding alone do not count. Exact D1/D7/D30 retention includes only users for whom that complete UTC day has elapsed. Weekly cohorts display null for unobservable weeks, never zero. A cohort week must have fully elapsed for all cohort members before the aggregate cell is shown.
Funnel: unique first-time browser visitors → linked account → onboarding → generated goal → first meal → three distinct active dates in first seven days after first meal → active on registration day+7. Milestones must occur in order and by UTC now. Returning registrations without a linked visitor cannot enter this visitor-acquisition funnel. It is a browser/device measure, not unique humans. Funnel conversion null when prior stage count is zero. Largest drop-off uses percentage-point stage conversion loss among nonempty denominators.
A/B assignment is persistent, 1:1 by UUID hash, at onboarding. Variant B receives the dashboard insight card; A does not. Seven-day outcome windows must be complete before results count. Simulated outcomes are labeled; there is no causal lift claim or automatic winner selection.
